# 事故复盘：2026-10-27 价格尺度事故（R0）

> 结论先行：**市场规则全部按设计工作，但比值型规则在数学上无法发现尺度型错误**。
> 校验基准与被校验值取自同一个污染源时，规则形同虚设。已用 v0.7.5
> 跨时点基准门禁堵住，本文记录五道防线全漏的机理与教训。

## 1. 事故概要

- **时间**：2026-10-27 09:32:06（Pi）
- **成交**：买入 000792（盐湖股份）100 股 @175.97（计划 #14）
- **真实价**：22.24（不复权/前复权），虚高 **691%（7.9 倍）**
- **损害**：虚付 ~15,372；09:32 NAV 快照虚记总值 155,999（+56%）；
  持仓成本/peak 污染；条件单 #29 按假价 180 挂出
- **处置**：按计划基准价 22.25 冲正（退 15,372），删污染 NAV，取消 #29，
  `op_log data:incident` 留痕，改前备份 `paper_account.db.bak-incident-20261027`
- **源头**：v0.7.3 已切 `close_qfq`；本事故发生在部署前 78 分钟的最后窗口

## 2. 机理：价格链路在哪一步变脏

```
计划生成（10-26 晚，v0.7.0，本地前复权）      → 基准价 22.25 ✓
v0.7.1/v0.7.2（10-27 02:34 部署）
  执行侧 price_map/bar_source 改走母库
  母库取 close_adj（后复权）= 175.96        → 污染源注入 ✗
执行（09:32，v0.7.2）
  price_map → px = 175.96 → 限价单成交
```

关键：`loop.py` 中计划价只在 `price_map` **缺价**时兜底（`price_source=last_close`），
price_map 有价时直接用——污染在上游，兜底锚永远没机会生效。

## 3. 五道防线为什么全漏

| # | 防线 | 为什么没拦 | 教训 |
|---|------|-----------|------|
| 1 | **涨跌停带**（`paper_broker.py:310-318`） | `order.prev_close` 取自同一份污染 bars（`loop.py:1096`：`prev=bars[-2].close`）。昨收 175.96×1.1=193.6，订单 175.96 在带内。**比值恒为 1，带宽检查对尺度错误零敏感** | 校验基准必须独立于被校验值；同源自洽 ≠ 正确 |
| 2 | **high/low 穿价检查**（`:320-324`） | `ref_high/ref_low` 同样取自污染 bars（`loop.py:1101-1102`），175.96 恰在污染 K 线区间内 | 同上 |
| 3 | **单笔金额上限**（20,000） | 污染价×100=17,596 < 20,000，**"合格"**通过。尺度错误恰好落在窗口内纯属量级巧合 | 金额窗口校验对尺度错误只有偶然敏感性 |
| 4 | **费用地板**（min_ticket 5,000） | 真实价 22.25×100=2,225 < 5,000 **本来会被拒**；污染价 17,596 > 5,000 反而放行。**地板被污染价抬过了自己** | 下限校验同样依赖价格正确性 |
| 5 | **风控 check_signal**（仓位/回撤/日亏） | 全部以 `total_value`/`prices` 计算，同源污染。且买入时仓位占比 17,596/155,999≈11% 看似无害 | 组合级校验的输入价必须可信 |

**唯一能拦的**：跨时点/跨源的独立基准（计划价 22.25 vs 执行价 175.96，偏离 691%）。
v0.7.5 `max_price_deviation=0.30` 门禁即此（`loop.py` `_execute_actions`，
事故重演单测 `test_price_deviation_gate_rejects_scale_pollution` 锁定）。

## 4. 为什么测试没拦住（流程教训）

1. **单测只测"规则在正确数据下的行为"**：涨跌停/金额/地板的用例都喂了合理价格，
   没有"数据本身是脏的"用例类别 → 新增对抗性测试类：**喂病数据，断言拒单**。
2. **P6.5 切库验证只对照了信号差异**（`data compare` 交叉数/相关性），没对照
   **价格量级**本身；相关性 1.0 完全不暴露尺度差（尺度不改变相关性）。
3. **配置字段接线断层无回归测试**：`require_stop` 有字段无接线（本轮补 R2.2 反射测试）。
4. **部署无灰度**：执行侧数据源切换（v0.7.1）在凌晨部署，09:32 直接进实盘；
   数据源类变更应先跑 `data coverage/compare` 门禁再放行 cron。

## 5. 提炼的检查模式（进 AGENTS.md）

1. **独立基准原则**：任何"值 vs 基准"的校验，基准必须与值**不同源、不同时点**；
   同源校验只能防逻辑 bug，防不了数据 bug。
2. **量级 sanity**：新数据字段进入执行链/账本前，必过绝对量级门禁
  （价格 ≤0 或 >10 万拒；比值偏离 >阈值拒），不依赖相对校验。
3. **接线三件套**：新配置字段必须同时有 yaml 键 + 读取代码 + 反射测试，
   缺一不合并。
4. **数据源切换 = 高危变更**：切库类改动上线前必须跑覆盖度+量级对照，
   部署后第一笔成交人工复核。
