# 开源框架迁移重构方案（refactor-plan-open-source）

> 依据：用户指令（2026-10-27）——**量化交易核心必须使用成熟开源框架，
> 零自研**；"给 AI 提供数据和参考策略"的部分不属于量化系统，可保留。
> 本方案为决策文档：**用户拍板后才动代码**；执行进度回写
> `docs/founding-mandate.md` §5。

## 1. 分层架构（2026-10-27 用户修正版，取代原"零自研"表述）

> 用户定调：「零自研不现实，不然没法开发。把计算、市场等复杂的部分交给
> 社区成熟框架，有了量化框架后把我们本来想要实现的功能盖上去；同时理性
> 审视社区部分；不能再有 AI 随意下单还通过的事情发生。」
> 原"零自研"红线**撤回**，改为下列三层：

### L1 量化核心层（计算/市场语义）—— 社区框架，不自研
撮合/账本/T+1/涨跌停/费用/滑点/回测/风控**判定**。框架缺口的 A股合规判定
优先用框架扩展点，实在没有才登记为「自研保留件」并配 parity 门禁。
**可判定红线**（采纳员工 P2-7）：任何影响成交价、持仓、盈亏、下单/拒绝
结论的**数值**，必须来自框架 API 返回值。

### L2 功能层（我们本来要实现的产品功能）—— 自研，盖在框架之上
AI 决策链（上下文/决策/审计）、数据供给（akshare/母库适配器）、面板/CLI/
op_log、cron 运维、**安全门禁**（尺度闸/执行价偏离闸/条件单闸/止损门禁/
配置接线回归——门禁消费框架 API 的数值做 fail-closed 校验，本身不计价）。
这一层的自研是产品本身，合理且必须。

### L3 审查层（防走歪）—— 双同事审查制
同事 A（Qoder）：选型/spike/对我方案的反驳审查；同事 B（Hermes）：
现网 correctness 独立审查（H 系列）。**我的代码与决策推送后须经至少一位
同事复核**；配套：parity 门禁、事故回归门禁、NaN 非有限值门禁。

## 3. 推荐架构：双框架

```
┌─────────────────── 保留自研（量化系统外） ───────────────────┐
│ akshare/SQLite/母库 ──► 数据适配器 ──┐    AI 决策链(LLM/审计) │
│ 面板/CLI/op_log ◄── 状态订阅 ◄───┤    └──动作/条件翻译器──┤
└──────────────────────────────────┼───────────────────── ┘
                                   ▼
 ┌── rqalpha 6.x（回测线）──┐   ┌── vnpy 4.x（交易线，常驻）──┐
 │ 策略回放/成交/费用/资金曲线   │   │ EventEngine + MatchingEngine  │
 │ optimize/walkforward 由胶水  │   │ 账户(T+1 冻结)/风控/条件单    │
 │ 调度，判定全在 rqalpha 内     │◄──┤ AI/规则下单走 vnpy Order API  │
 └────────────────────────┘   └──────────────────────────┘
```

- **回测线 → rqalpha**：接管 `engine/backtest.py`/`optimize.py` 的**判定**；
  我们的 walkforward 调度、回测指纹（`provenance.py`）保留为胶水/审计。
- **交易线 → vnpy**：接管 `PaperBroker`/`RiskManager`/`runner`/`ConditionRunner`
  的**判定与成交路径**；AI/引擎/面板全部改经 vnpy 下单 API 与账户查询。
- **Python 统一 3.13**：本地建 3.13 venv（3.14 下 vnpy 只能装到 4.0.0），Pi 已是 3.13.5。

### 5.2 M1 归口裁决（主 AI，2026-10-28；依据 T7/T9/T10 取证）

> T9 实测：原三条容差**结构性不可达**（80 vs 108 笔、权益差 −8.01%、14 笔
> 静默丢单），根因六个语义差。四项阻塞决策现已裁决：

- **D1 撮合时点 = T+1 开盘（无未来函数不可妥协）**：rqalpha 当日收盘撮合
  （`sys_simulation/mod.py:59-62` 强制）**不接受**为最终口径。路径：
  ① **S 级信号门禁立即执行**（信号集合与撮合时点无关）；② 分钟频率实验
  确认 rqalpha 能否实现 T+1 开盘（T18）；③ M2 模拟线事件源天然支持 T+1
  （T13 取证后为正式路径）。达成前 F 级容差按实测固有价差推导并书面声明。
- **D2 parity 用股数语义**：两边固定 100 股/信号，隔离 sizing 差异。
  「金额不足一手 → 静默 skipped」（14 笔）是**独立缺陷**（违反纪律 4），
  立即修报告化（T17），不阻塞 parity。
- **D3 复权锚点 = route B 全线**（T7 取证：route A 对 600519 双重计入
  2,802.42 元/2.31%）：回测 = bundle raw+因子+分红三件套；**M2 模拟线 store
  喂原始价**（母库 `close_raw` 优先、akshare `adjust=""` 兜底），复权视图交
  rqalpha `adjust`；AI 上下文 qfq 展示保留（展示层，不进引擎）。
  `m1-data-adapter.md` §2"实时线喂 close_qfq"据此**修正**。
- **D4 过户费 = 自定义 `AbstractTransactionCostDecider`**（框架官方扩展点，
  L1 缺口正解，不算自研核心）；parity 数值锁定（卖 10,000 元：我方 10.1000
  vs rqalpha 默认 13.0000）。rqalpha 分红**全额入账无红利税** = 与我们现行
  简化（合规表 #16）一致，登记为已知差异。

### 7.2 推理（为什么是这个结构）

1. **硬门槛排序**：本项目的不可妥协项是 ①A股口径（T+1/涨跌停/费用/整手）
   ②回测与模拟撮合**同一引擎**（路线图纪律 3）③Pi arm64 + Windows 双平台可装
   ④活跃维护。现有证据下**只有 rqalpha 全部已实证**：
   - 员工 Windows 端到端跑通（bundle 3.3GB、回测返回 summary）；
   - 我的 Pi arm64 spike：装好、导入成功、MainEngine 级别无问题（rqalpha 侧）；
   - A股语义源码取证最全（2023 印花税日期/涨跌停/模拟撮合器/T+1 账户）。
2. **但 akquant 是唯一可能翻盘的挑战者**：MIT 许可（永久消除合规张力）+
   与 akshare 同门（数据适配天然）+ Rust 内核 + 高频维护。它输在哪没验证过
   （模拟撮合能力、aarch64 轮子）——**用半天、两个否决性问题验证，
   比全量三选一打分便宜且同样有效**。通过 → 终选改 akquant；不通过 → rqalpha 定案。
3. **为什么不再漫无目的打分**：其余维度（许可已接受、bundle 已留、NaN 门禁
   已列入 M1 条款）不再是决策变量；决策树只剩一根分叉，测那根分叉即可。
4. **Python 版本**：rqalpha 在 3.14（开发机）与 3.13（Pi）**双端实测可装**，
   **不降级**——原 §7-C"全线 3.13"随 vnpy 冻结一并作废（员工 P1-3 正确）。
5. **账本历史**：原则维持"归档 + 切换日新开账"（§4），随终选框架在 M2 重确认。

## 5.1 M1 验收门禁（采纳员工 `report-defect-attribution.md` §6，2026-10-27）

原则：市场语义在 L1 框架内；门禁在 L2 且必须 fail-closed。**不绿不合**：

1. **事故日回归（最高优先）**：喂 `close_adj=175.96 / 真实价 22.24` 的合成母库
   + 当日计划，断言下单被拒且拒因含"偏离基准价"；不绿不许合任何撮合改动。
2. **无基准 = 拒单**（H-1 已修）：`_ref<=0/NaN` → 独立拒绝分支（fail-closed）。
3. **缺现价 = 拒挂**（H-4 已修）：`prices` 提供但缺价 → `price_*` 条件进
   `parse_rejected`，禁止"行情抖动 → 尺度校验自动放行"。
4. **涨跌停带必须在引擎内**（T6 否决理由）：验收方式=读框架源码给 `文件:行`，
   不接受"外层拦一下"。（此条同时是未来任何框架更换的自动筛子。）
5. **非有限值门禁**：框架返回的 `sharpe/alpha/任何金额` 进排名/面板/账本前过
   `math.isfinite`，违反即整轮作废并落 `op_log`（rqalpha 越界窗口只吐 NaN 不抛错）。
6. **钱类缺陷清零口径**：`report-defect-attribution.md` §2 的 6 条钱类逐条
   写成回归测试；迁移前后各跑一次，**同一份测试证明 L1 替换没把合规能力换丢**。
7. **口径唯一**：`data.daily_source` 真做成 mother-only（M-1 已修）或删掉该取值；
   禁止文档承诺与代码行为不一致。
8. **数据适配器入口 sanity（T29-P1 采纳，2026-10-29 主 AI 裁决）**：喂入新引擎的
   任何 bar 必须过**绝对量级 sanity（0 < close < 上限）+ 跨源尺度对照**，且
   **L2 侧既有 sanity（T16-5/H-7）不因迁移豁免或删除**。依据：T29 实测 rqalpha
   对 bar 级尺度污染只有"半条防线"——涨跌停带拦**下单价**（限价单经
   `price_validator`，市价单经 `matcher/base.py:206-216`），但**估值/净值/指标
   直接吃 bar close，无任何量级校验**——错 6.4× 的 bar 会一路照算不报错。
   M1 阶段验收 = L2 sanity 测试在案不删（✅ T16-5）；M2 适配器建成时按此条验收。

### 5.8 M3 两阶段修订（主 AI 裁决 2026-10-30；依 T52 产品路径实测 R1-R4）

**T52 照出的物理事实**（独立取证 + 产品路径实测，主 AI 全部采纳）：
1. **④（裸调撮合器）不可行**——P5 铁证：裸 matcher 卖当日买入的票 = FILLED 且
   closable 写成 **−100**（T+1 穿透 + 账写坏）；Environment/event_bus 是硬依赖。
2. **1d 会话的"每分钟跳"= 日 bar 重放**——成交价恒为当日收盘价（实测三跳
   全 22.10，该日高低价 22.51/22.05）⇒ 10:00 的决策按 15:00 的价格成交 =
   **未来函数**（纪律 3 禁止）；且 1d 会话里盘中止损根本不触发。
3. **框架账本只认会话内成交**——盘中实时执行（旧线 PaperBroker）的成交
   **进不了** rqalpha 账本（外部注入会重蹈 P5）⇒ 分钟线攒够前，"rqalpha
   接管生产撮合/账本"物理上不可完成。

**裁决：M3 修订为两阶段**——
- **M3a（本周末执行）：rqalpha 日终独立校核门禁**。每晚日终会话（当日窗口
  首跑，非续跑）以真实数据独立重算当日账（成交/费用三分量/NAV），与生产
  账本逐字段对账；**差异超阈 ⇒ `op_log[parity:diff]` 红 + 停线告警**
  （不是影子"看看"，是门禁"超阈停"）。性质：旧线继续执行盘中，
  **账目正确性每晚由框架盖章**——硬规则 0 的过渡态满足（计价判定来自
  框架 API），错账最长存活一个交易日。
- **M3b（分钟线攒够后，T26 起约 2-3 个月）：②常驻分钟会话全量接管**
  （盘中执行 + 账本 + 结算进框架，旧线下线）——分钟线是物理前置，
  无法用工程加速。
- **R2 定性落槌**：1d 会话**不做每分钟跳**（未来函数风险 + 无盘中语义），
  日终一跳；盘中成交口径标注（AGENTS 合规表新增"简化"项：盘中按实时价，
  日终校核按收盘价，差 ∈ F 级容差）。
- **R1（overlay 续跑不装）**：M3a 日终首跑不触发（before_trading 正常），
  但**必须修**（防御同日重跑与 M3b）——T55；**R3 跨日解冻取证**并入 T55；
