# report-defect-attribution — 代码问题到底有多大：量化归因（L1/L2/L3 版）

作者：员工 AI（Qoder）｜2026-10-27 深夜｜读者：主 AI、Hermes、以及未来接手的任何人
用途：**把"我们 bug 修不完"从感觉变成数字**；给 M1 验收靶子；给 L3 双审的分工依据。
口径与术语对齐 `docs/founding-mandate.md` 的用户修正路线：**L1 计算/市场语义交框架、
L2 功能层自研盖上去、L3 双同事审查**。

> 另一半真相同样要说：**61% 的缺陷住在 L2，换框架一行都不会自动变好。**

## 5. 反直觉但必须写进决策的两条

1. **换框架消灭的是"钱的 bug"，不是"bug 总量"**。
   11/18 缺陷住在 L2（AI 计划生命周期 H-2/H-3/H-5、母库数据缝 R-②/R-⑥/H-6/H-7/H-8、
   配置断层 R-①、死配置 M-1）。这些**与框架无关**，M1–M4 走完它们还在。
   ⇒ L3 双审的火力**不能**全押在迁移上。
2. **H-7 是我们自己造的缺陷类别，框架不治**。
   它源于"我们坚持同时吃 akshare 与母库两个口径"。§7.3 已经把口径归口定死
   （新引擎只吃两源之一，bundle 只供日历/权息/停牌/ST 元数据）——这条定死后，
   H-7 这类跨源对照洞才真正关闭。**在归口落地前，任何"上框架"都不等于安全。**

## 6. 给 M1 的验收靶子（可直接变成测试；建议主 AI 收进 M1 条款）

原则：**市场语义在 L1 框架内；门禁在 L2 且必须 fail-closed**（用户 2026-10-27 深夜指令）。

1. **事故日回归（最高优先）**：喂 `close_adj=175.96 / 真实价 22.24` 的合成母库 + 当日计划，
   断言下单被拒且拒因含"偏离基准价"；这条不绿不许合任何撮合改动。
2. **无基准 = 拒单**（修 H-1）：`all_bars` 缺该标的或 `_ref<=0` → `_dev=+inf`，走独立拒绝分支。
3. **缺现价 = 拒挂**（修 H-4）：`prices` 为空时 `price_*` 条件进 `parse_rejected`，
   禁止"行情抖动 → 尺度校验自动放行"。
4. **涨跌停带必须在引擎内**（T6 的否决理由）：验收方式=读框架源码给出 `文件:行`，
   不接受"外层拦一下"。（此条同时是未来任何框架更换的自动筛子。）
5. **非有限值门禁**：框架返回的 `sharpe/alpha/任何金额` 进排名/面板/账本前过
   `math.isfinite`，违反即整轮作废并落 `op_log`（rqalpha 实测在越界窗口只吐 NaN + warning，
   不抛错——见 `report-t5.md` §10.3）。
6. **钱类缺陷清零口径**：把本报告 §2 的 6 条钱类逐条写成回归测试；
   迁移前后各跑一次，**用同一份测试证明 L1 替换没有把合规能力换丢**。
7. **口径唯一**：`data.daily_source` 要么真做成 mother-only，要么删掉该取值（M-1）；
   禁止文档承诺"只用母库"而代码等同 auto。
