## 3. 为什么 M4a 必须自研（而非直接上 QMT/QLib）

1. **信号源是私有的**：买卖依据是本系统 AI 输出的 `signal/confidence/buy_zone/target/stop`，外部平台吃不进这套信号，只能自研撮合。
2. **频率对得上**：日频选股 + 周复盘，不需要 tick/分钟线，自研日K撮合足够精确，复杂度可控。
3. **零依赖跑生产服务器**：SQLite + 已有表，不引入任何新依赖，不违背"生产服务器性能"约束（roadmap 设计模式）。
4. **blameless 验证**：纸盘亏了先怀疑信号质量，而不是怀疑券商仿真环境；M4a 是 M4c 的前置对照组。

## 4. M4a 设计草案（`src/paper/`）

### 4.1 新表（SQLite，复用现有 DB）

| 表 | 内容 |
|---|---|
| `paper_account` | 虚拟资金（初始 100 万，可配）、累计收益 |
| `paper_orders` | 委托：code/方向/价格/数量/信号来源/状态（已报→已成/已撤/废单） |
| `paper_trades` | 成交：价格/数量/费用明细 |
| `paper_positions` | 持仓：数量/可用数量（T+1 冻结）/均价/浮盈 |
| `paper_nav` | 每日净值（接净值曲线图，复用 klinecharts 或 SVG） |

### 4.2 信号→委托规则（v1，只做多、不做空）

- 输入：`screening_result.ai_trade_strategy`（signal=BUY + confidence + buy_zone）与 `ai_watchlist` 周决议。
- BUY 且现价 ∈ buy_zone → 次日开盘市价委托（T+1 可用资金内，单股 ≤20% 总资产）。
- 止损/止盈/AVOID → 次日开盘委托卖出可用持仓。
- 调仓频率：跟随周复盘（低频，避免过度交易吞掉收益）。

### 4.3 A股撮合建模清单（回测与纸盘共用，缺一即失真）

- [x] T+1（当日买入不可卖，用 `可用数量` 建模）
- [x] 涨停买不到 / 跌停卖不出（按 `high/low` 是否触板判定）
- [x] 100 股整数倍，不足 100 股只可一次性卖出
- [x] 费用：佣金万2.5最低5元（双边）/ 印花税卖出 0.5‰ / 过户费 0.01‰（双边）——以券商实际为准，写入 `config.yaml`
- [x] 滑点：默认 0.1%，可配
- [x] 停牌：无 K 线则当日不可交易（`kline_daily` 缺数据即停牌假设）
- [ ] 连续竞价价格笼子 ±2%（v2，实盘对接前补）

### 4.4 风控闸（纸盘即练兵，与未来实盘同一套）

单股 ≤20% · 总仓位 ≤80% · 个股浮亏 -7% 强制离场 · 账户回撤 -15% 当日禁买。
触发全部记 `paper_orders`（状态=风控拦截），面板可查——**纸盘阶段就要把风控当实盘跑**。

### 4.5 BrokerAdapter（M4c 预埋，现在只定接口）

```python
class BrokerAdapter:
    def place_order(self, code, direction, price, volume) -> str: ...   # 返回 broker 侧 order_id
    def cancel_order(self, order_id: str) -> bool: ...
    def get_positions(self) -> list[dict]: ...
    def get_account(self) -> dict: ...

class PaperBroker(BrokerAdapter): ...   # M4a：库内撮合
class QmtBroker(BrokerAdapter): ...     # M4c：xtquant 懒加载，Windows only
class PTradeBroker(BrokerAdapter): ...  # M4c 备选
```

纸盘 UI 与未来实盘 UI 共用同一套持仓/委托/净值展示——切 broker 不换界面。

## 5. M4b QLib 离线研究（不进生产服务器）

- 用途：验证"筛选分数 / AI signal 是否有超额"——TopK 回测（每期取 Top20 等权，月/周再平衡），基准沪深300。
- 数据：`scripts/get_data.py qlib_data --region cn` 官方 CN 包，或自研导出 `kline_daily + financial_summary → qlib .bin`（推荐后者：与库内数据同源，避免双数据源打架）。
- 产出物：只回流**结论**（如"ROE_5y>15 且 score>80 分组年化超额 X%"）到筛选权重，不回流代码。
- 硬件：用户 PC 或云主机（训练要内存/CPU，低内存主机免谈）。

## 6. M4c 券商仿真（需 Windows + 券商账户，用户侧执行）

- 首选 **QMT 完整版模拟运行**：策略在"模型交易→模拟"跑，信号只显示不下单；或接模拟柜台真撮合。xtquant 本地 SDK 与 `QmtBroker` 对接。
- 备选 **PTrade 仿真**：券商托管，稳；注意 Python 版本（多为 3.5）与无 pip 内网限制，策略需迁就写法。
- 达标线（进 M4d 的门）：仿真 3 个月，收益为正且最大回撤 <15%，且与 M4a 纸盘偏差可解释（偏差>5% 先查滑点/撮合假设，不查策略）。

## 7. 合规与红线

- 本项目所有"交易"在 M4d 前都是模拟，面板必须醒目标注"虚拟盘，非实盘"。
- 不碰：场外配资、程序化高频（报撤频率合规线）、无资质投顾式收费荐股。
- QMT/PTrade 账号、密钥只存用户侧 Windows，**永不进 Git、不进生产服务器**。
