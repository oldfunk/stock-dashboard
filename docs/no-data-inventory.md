## 三、财务侧 321 只：整个北交所不在采集链路里

**根因是市场后缀二分。** 仓内两个映射函数都是同一个规则：

| 函数 | 规则 | 对 920000 的输出 | 应该是 |
|---|---|---|---|
| `balance_sheet_fetcher._em_symbol()` | `6/9 开头 → SH，否则 SZ` | `SH920000` | `BJ920000`（或东财 F10 的市场号 3） |
| `mainfin_fetcher._secucode()` | `6/9 开头 → .SH，否则 .SZ` | `920000.SH` | **`920000.BJ`** |

北交所新号段 920 以 `9` 开头，被当成沪市；旧号段 83/87/43 以其他数字开头，被当成深市。
对照实测（同一只 920000 安徽凤凰）：

```
东财 datacenter  RPT_F10_FINANCE_MAINFINADATA
  filter=(SECUCODE="920000.BJ")  -> 5 行，最新报告期 2026-09-30
  filter=(SECUCODE="920000.SH")  -> 0 行
  filter=(SECUCODE="920000.SZ")  -> 0 行
东财 K 线  push2his stock/kline/get
  secid=0.920000 -> 1,417 根日线（2020-12-23 .. 2026-10-30）
  secid=1.920000 -> 0 根
```

**上游有完整数据，是我们的映射把它挡在门外。** 库内佐证：

- 快照里 920 号段 **321 只**，其中有日线的 **0** 只、有财务的 **0** 只；
- `kline_daily` 里 `8%`/`4%` 号段行数 **0**（旧北交所号段同样整体缺席）；
- 对照组科创板 688 号段：快照 609 只、有日线 609 只、有财务 609 只——
  所以这不是"新号段本来就没数据"，而是号段→市场映射缺了北交所这一支。

321 只的逐只证据行完全同形（"北交所号段（920）、快照有行但行情/财务均为 0 行"），
所以这里不逐行粘表；`python scripts/audit_no_data.py --format md` 会输出全部 334 行。
要把它固化进仓库我再补一版，只是那种表一漂移就得重抄。

## 四、归因顺带挖出的两个缺陷（本件只报不修）

**缺陷 A：北交所整体缺席（321 只，快照 5,527 只的 5.8%）**
改法不止一处：`_em_symbol` / `_secucode` 的前缀规则、腾讯与新浪的 symbol 前缀、
`stock_zh_a_hist` 类接口是否覆盖 BJ（需要另走 BJ 接口）。这是一件跨 collector 的
独立工作，请派单；我不在归因这一件里顺手改采集口径。

**缺陷 B：空响应被记 `no_data`，之后被进度表永久排除**
301139 *ST元道 名字不带"退"、末根日线 2026-10-27 还在交易，却在 2026-10-28 被记
`no_data`。`no_data` 的语义是"这只票没有数据"，而东财限流时的表现恰好也是空响应
（N10 处理的就是那个现象）——两者不分开，**一次限流就能让一只活跃票从此不再被采集**，
而且日志上一切正常。两个出口请裁定：

1. 空响应先换源复核（仓内已有腾讯/新浪路径）再定性 `no_data` / `partial`；
2. 或按周期性 `--retry-no-data` 复跑 `no_data` 集合（本仓已有这个参数先例）。

我倾向 1（它把错误挡在记账之前），但那要动回填侧的判败逻辑，量级比本件大，不擅自做。
