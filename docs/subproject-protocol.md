# 子项目协作协议（母整合 / 子施工 / 人包工头）

> 适用：母项目（Stock Dashboard）+ 任意 vendored 子项目。新增子项目时复制本文件机制，
> 只需重填 §8 清单里的三表契约与路径。本文件是母方立场；跨仓争议由人裁决。

## 1. 角色

1. 母项目 = **整合方**：拥有接缝（§3），负责 vendor 拉取、门禁验证、生产部署。
2. 子项目 = **施工方**：拥有域内全部代码，自主开发、单测、打 tag 发版。
3. 人 = **包工头**：跨仓争议唯一裁决；负责把母方 Issue 转交子方。

## 2. 流向（单向 tag 流）

1. 子项目只在自家仓库开发，**母方永不反向推分支**。
2. 子方按功能打 tag（`v0.x.y` + changelog + 单测证据）；母方**只跟 tag，不跟 main**。
3. Vendor 命令：`git subtree pull --prefix=<dir> <remote> <tag> --squash`（nightly 分支操作）。
4. 母方按需拉取，不承诺跟进时效；账本记录 vendored 版本号（当 lockfile 用）。

## 3. Bug 分诊（按位置，不按层级）

| 位置 | 归属 | 例子 |
|------|------|------|
| 接缝（两边连接处） | 母项目修 | pool 只读、import 路径、配置命名空间、DB 路径/CWD、端口、面板跳转 |
| 域内（子目录内部逻辑） | 子项目修 | 策略、撮合、风控、面板内部、子单测 |

判定规则：只改子目录文件能修 → 域内；必须同时懂两边才能修 → 接缝。
母方在巨型 repo 里修小 bug 又贵又险，子方在小 repo 里修又快又准——分诊依据是注意力成本，不是权力。

## 4. Issue 工单（唯一跨仓通道）

1. 域内 bug 母方不修，只写 Issue：标题 `[bug]` + 复现步骤 + 期望行为 + 母方版本号。
2. 只提**接口级需求**（要什么、验收标准），不写实现。
3. 等子方 tag，母方 vendor 驗收。不催、不代写。

## 5. Hotfix 例外（救生产线 only）

1. 仅当生产故障且等不及 tag 时，母方可直改 vendored。
2. 24h 内必须在子方仓库补 Issue（含复现）+ PR；母方账本留痕。
3. 下次 vendor 冲突一律取上游，hotfix 行自动作废（除非子方已合入）。

## 6. Vendor 门禁

1. 子方契约表（拥有/只读/永不碰）逐条核对，不满足不开合。
2. 生产 worktree `gate.sh` 全绿 + 服务重启验证（改路由/模板/采集才重启）。
3. 机械适配（import 路径、配置命名空间）必须单列 commit，逐条列出，不得顺手改逻辑。

## 7. 反模式（出现即叫停）

1. 母方直改 vendored（§5 除外）。
2. 同一修复双推两个仓库（hash 分叉 = 未来的冲突，realtime 三行两边同修即实证）。
3. 母方跟对方 main（只跟 tag）。
4. 跨 repo 代写代码（用 Issue 代替）。

## 8. 新子项目开张清单（复制即用）

- [ ] 独立仓库 + 三表契约文件（拥有/只读/永不碰，逐字填）。
- [ ] tag 发版流（`v0.x.y` + changelog + 单测证据）；首 tag 即 vendor 基线。
- [ ] 母方 `docs/architecture.md` 登记边界；母方只加**接缝测试位**（跳转通、池源可解、列表不断），域内测试归子方。
- [ ] 母方 `.gitignore` 锁死子方密钥与运行时产物；`git check-ignore` 逐项验证。
- [ ] 双方公开前各做一次安全审计（密钥/身份/DB/CI 面），交叉复核。
- [ ] 本文件复制给新子项目，人逐条确认。
