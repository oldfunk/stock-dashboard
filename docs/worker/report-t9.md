## 结论（先给判定）

**§5.1-6 的三条容差（成交笔数差 0 / 费用差 <1e-6 / 收益差 <0.1pp）在当前语义组合下不可达，

## 1. 实验设计：为什么必须分层

同一规则跑两个引擎时，差异可能来自三处：**数据**（价源/复权锚点）、**判定**（信号窗）、
**执行**（撮合时点/费用/下单单位）。只跑一次会把三者混成一团，所以我做三层：

| 层 | 配置 | 目的 |
|---|---|---|
| L1 | 旧引擎吃 bundle **原始价**，滑点 0，费率我们那套 | 与 rqalpha 同一份价，差异只可能来自引擎语义 |
| L2 | 旧引擎吃**前复权（锚=窗口末）**（= 现网 qfq 入库口径） | 单独量化"复权锚点"对信号与收益的影响 |
| L1b | rqalpha 原生 bundle，滑点 0，`stock_commission_multiplier=0.3125`（把万 8 换算成万 2.5） | 引擎腿 |

## 3. 六个结构性语义差（每条给证据，这是报告的核心）

1. **撮合时点**：旧 = T 收盘信号 → **T+1 开盘价**（`engine/backtest.py:62-67` 类文档语义 +
   `_exec_price` 用开盘参考）；rqalpha 日线 = **当日收盘**（`sys_simulation/mod.py:59-62` 强制）。
   ⇒ 时点差 mean 1.57 天、价格差 mean 0.362%（实测 L4）。**未归口 ⇒ 逐笔对照无意义。**
2. **下单单位语义**：旧 = 按**金额** `size_for_value(price, value)` 向下取整到整手；
   rqalpha 策略 = 按**股数** `order_shares(100)`。
   ⇒ 价格上行时旧引擎买 0 手、信号**静默降级为 skipped**（实测 14 笔"金额不足一手"
   + 连带 15 笔"无可卖持仓"）。**这是我们引擎的真实缺陷类别**：钱没进去、统计里也几乎看不见，
   与路线图纪律 4「不静默」冲突 ⇒ 建议无论迁移与否都单独修。
3. **费用项**：过戸费缺失（§L3 + T10 余额算术）；佣金默认万 8 需乘数换算。
4. **复权锚点**：见 §2 L2 表；rqalpha 读时锚=当日，我们入库锚=同步日。
5. **分红入账**：rqalpha 引擎内在除息日入账（T10 实测 Δcash=+900.00、总值 +10.00）；
   旧引擎与 `PaperBroker` **完全不处理分红**（我们靠人工 `corporate apply`）。
   ⇒ 跨除权日的两个净值序列**天然不可比**，这是收益差的主要来源之一，也是"上框架最实质的收益"。
6. **剩余 26 笔缺口我没能归因**（坦白）：排除组合风控（实测无差异）、股数（0 差异）后仍在。
   候选（未证实）：`once` 每日语义、涨跌停一字板拒单、T+1 冻结路径、rqalpha 允许同规则多次触发。
   ⇒ 这正是 T12（Hermes 独立复核）该收口的点；我提供脚本与两种 value 设置，
   请不要把"26 笔"当成已解释项签进 M1。

## 4. 建议：把 §5.1-6 改成两级门禁

| 级 | 内容 | 可签容差 |
|---|---|---|
| **S 级（严）** | **信号集合一致性**：同 symbol+side，日期差 ≤1 交易日；用同一价源同一锚 | 匹配率 ≥95%，未匹配逐笔必须书面归因 |
| **F 级（松，给定式）** | **财务级**：不再拍"收益 <0.1pp"，改为「按撮合时点固有价差 × 暴露仓位」推导 | 例：mean 0.375%/笔 × 平均持仓占比 ⇒ 容差算出来是多少就是多少，写进文档 |
| 硬门禁（不变） | 成交笔数差 0 仅在**同一撮合语义**下要求（先做决策 D1） | — |
