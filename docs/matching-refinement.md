# 撮合细化设计（M2 / D1）

> 状态：**设计 + 回归清单，未改执行代码**（2026-11-28）。
> 目的：把当前“日线收盘信号 → T+1 开盘价全额成交”的简化，逐项列清楚；
> 先定口径和验收，再单独开代码分支。**不在 v0.12 发布前改撮合。**

## 1. 当前真实行为（代码事实）

| 环节 | 当前 | 代码位置 |
|---|---|---|
| 成交价 | 限价 ± 固定滑点 0.01 | `PaperBroker._apply_slippage` |
| 成交量 | 订单量**全额成交**，无市场成交量约束 | `PaperBroker.submit_order` |
| 涨跌停价 | 只拒绝“价格越过涨跌停” | `PaperBroker.submit_order` |
| 一字板 | 回测：开盘价触板则保守不成交；实盘 broker **不判** | `Backtest` / `PaperBroker` |
| 集合竞价 | 不建模；日线路径用 T+1 开盘价 | `Backtest.run` |
| 部分成交 | 不建模（要么全成，要么拒） | `PaperBroker` |
| rqalpha 底座 | 由框架撮合（T+1/涨跌停/费用），子项目不再二次约束 | `AgentTrader._executor_of` |

结论：**当前不是“成交量/排队”模型，是“价格闸门 + 全额成交”模型。**
回测的一字板保守口径比实盘 broker 更严，两者并不完全同口径。

## 2. 目标与非目标

### 目标

1. 买单不得超过当日可成交量的一个比例（默认关闭，观察后启用）；
2. 一字涨停买不到、一字跌停卖不掉，回测/实盘同口径；
3. 卖出（止损/清仓）**永不因成交量比例被拦**；
4. 所有拒因可审计（`orders`/`ai:decide`/回测 `skipped`）；
5. rqalpha 底座不重复加约束（框架口径优先）。

### 非目标

- 不做逐笔/盘口队列仿真；
- 不做集合竞价撮合价发现；
- 不做部分成交（v1 先“拒单/通过”二值，避免账本半成交复杂度）；
- 不改 T+1、费用、涨跌停幅度（10%/20%/30%）；
- 不改变默认交易行为（v1 默认关闭）。

## 3. 提议口径（matching v1）

### 3.1 成交量参与率

配置（拟）：

```yaml
trading:
  # 0 = 关闭（v0.12 默认）；0.05 = 单笔最多占当日成交量 5%
  max_volume_participation: 0.0
```

规则：

- **仅买入**检查：`order.volume <= floor(ref_volume * rate / 100) * 100`；
- `ref_volume` 来自当日 bar 的成交量；缺失/为 0 ⇒ **fail-closed**（拒买），
  不拿“未知”当“无限量”；
- 卖出不检查（止损优先；卖出本身受可用持仓/跌停价约束）；
- 超出时**拒单**并写明“超当日成交量比例”，不静默改小数量；
- 回测同一函数、同一配置，输出 `skipped.why="超成交量比例"`；
- rqalpha 执行路径不调用该闸（框架自己处理），避免双重限制。

### 3.2 一字板/涨跌停排队近似

新增 `Order.ref_close`（可选）：

- 买入：若 `limit_price >= 涨停价 - tick` 且 `ref_close >= 涨停价 - tick`
  ⇒ 视为“收盘仍在涨停/排队不确定”，**保守拒买**；
- 卖出：若 `limit_price <= 跌停价 + tick` 且 `ref_close <= 跌停价 + tick`
  ⇒ 保守拒卖（卖不掉），拒因明确；
- `ref_low/ref_high` 只用于现有穿价检查，不单独推断一字板；
- 回测已有“开盘一字板”判断保留，并与 broker 共用 `limit_pct_for()`；
- `tick` 用 0.01 元（A 股价格最小变动），ST 5% 仍按当前简化 10% 处理，
  文档标注。

### 3.3 集合竞价

- 日线路径继续用 T+1 开盘价，**不假装能算竞价**；
- 分钟路径若首根 bar 是 09:30，仍按该 bar 成交，不引入 09:25 竞价；
- 文档明确：“竞价未建模，开盘价成交是简化，不是可复现竞价”；
- 未来若接分钟/盘口数据，再单独设计，不塞进 v1。

## 4. 回归清单（实现时必须全绿）

### 4.1 成交量

- [ ] 买入 100 股 / 当日量 1000、rate=0.1 → 通过；
- [ ] 买入 200 股 / 当日量 1000、rate=0.1 → 拒，原因含“成交量”；
- [ ] 买入 100 股 / 当日量缺失 → 拒（fail-closed）；
- [ ] 卖出 1000 股 / 当日量 100、rate=0.1 → **通过**（卖出豁免）；
- [ ] 回测同一场景 `skipped` 计数 +1，且不产生 fill；
- [ ] `rate=0` → 行为与现状完全一致（逐字节对照关键输出）。

### 4.2 涨跌停

- [ ] 买入价 = 涨停价、收盘仍在涨停 → 拒；
- [ ] 买入价 = 涨停价、盘中最低 < 涨停 → 通过（非一字）；
- [ ] 卖出价 = 跌停价、收盘仍在跌停 → 拒；
- [ ] 卖出价 = 跌停价、盘中最高 > 跌停 → 通过；
- [ ] 10%/20%/30% 三档 `limit_pct_for` 各一条；
- [ ] 回测“开盘一字板”与 broker 结论一致（同一 bar/prev_close）。

### 4.3 执行底座

- [ ] `executor=legacy` 走新闸；
- [ ] `executor=rqalpha` 不调用新闸（意图入队，框架撮合）；
- [ ] `_executor_of()` 无法判定时仍 fail-closed（现状保留）；
- [ ] dry-run 只报告“会拒/会过”，不写订单/成交。

### 4.4 审计

- [ ] 拒因进 `orders`/`ai:decide`，含订单量、当日量、rate、阈值；
- [ ] 回测 `skipped_sample` 可看到同类原因；
- [ ] 配置非法（负值/≥1/非数）启动失败，不静默回退 0。

## 5. 分阶段启用

1. **代码合并，默认 `0.0`（关闭）**：只加能力 + 测试，生产行为不变；
2. **回测/纸盘影子统计**：打开 rate=0.05，记录“本应拒”的数量与标的，
   不实际拒（`shadow=true`），观察 1–2 周；
3. **正式启用**：rate 由用户显式配置；先买后卖（卖出始终豁免）；
4. **复核**：一周内拒单/漏卖/回测-实盘差异为 0 红，再考虑提高复杂度
   （部分成交/竞价），否则保持简单。

## 6. 风险与回滚

- 风险：流动性差的票买入被拒 → AI 需降手数；止损卖出不受影响；
- 风险：`ref_volume` 缺失导致拒买 → 比“假成交”安全，但要在面板/流水可见；
- 回滚：`max_volume_participation: 0` 即回到现状；不改账本、不迁移数据；
- 发布：独立 tag/分支，不与策略/prompt 改动混在同一发布窗口。
