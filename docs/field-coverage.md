# 补充字段"取到率"口径（批10-b 方案 1，2026-10-30）

派工单原文：**"历史商誉只有 35% 年报行有值 → 修采集，目标 ≥85%"**。
取证证明那 35% **不是采集缺陷**，母方裁定改走方案 1：**不设百分比指标，只交事实**。
这份文档就是那个"事实"的口径与当前数值。

```bash
python scripts/report_field_coverage.py            # JSON
python scripts/report_field_coverage.py --format md
```

## 一、为什么原来那个指标不可达，也不该达

`cash / interest_bearing_debt / goodwill / total_assets / total_equity` 五个字段来自
**同一次**东财 F10 资产负债表请求（`balance_sheet_fetcher.fetch_balance_sheet_annual`）。
所以"这一行有没有被取到过"可以用兄弟字段判：同一行了给了 `total_assets`，
就不会是"请求失败"。

对 5 只 `goodwill` 为空但 `cash` 有值的票逐条看原始响应：

```
000968 / 600814 / 002315 / 601619 / 000400
  → GOODWILL 键存在、值为 None；同一行 MONETARYFUNDS 有数（13.5 亿 …75.3 亿）
正对照 601567 / 603707 / 000407
  → GOODWILL 给的就是数（1,203,649,015.41 等）——采集代码没坏
```

**东财对没有商誉的公司明确给 null。** 重跑采集（含 `--full-history`）一字节都不会变。
要把 35% 推到 85%，唯一路径是把"源确认无此项目"写成 `0`——那是造语义。而全仓
`grep goodwill` 的结论是：这一列**今天没有任何消费方**（只有采集器写、无一处读）。
"没有消费方的数据不值得为它冲指标"——这条已被母方记进 handoff 作为原则。

## 二、两个口径（同一份数据，别混用）

| 口径 | 分母 | 含义 |
|---|---|---|
| **有值率** | 全部年报行 | 把"源确认无"与"没采到"混在一起；原 85% 目标用的是它 |
| **取到率** | **这份资产负债表确实被取到过**的行（宽判据：五字段任一有值；严格判据：`total_assets` 有值） | 采集质量；剩下的差额是"源确认无此项目"，属事实 |

## 三、当前数值（nec 生产库，2026-10-30）

- 年报行 **93,309**；资产负债表确实取到过 **93,104** 行；严格判据（`total_assets` 有值）
  **93,101** 行——两个分母只差 3 行，说明分母本身是稳的。
- **整份资产负债表都没落地的行：205 行（0.22%）**。这才是唯一的采集缺陷类，
  且全部在 2016 年以前（2016–2025 每年均为 0），集中在个别票
  （`000987` 19 行、`000776` 13 行、`000686`/`000728`/`000783`/`600109` 各 12 行……）——
  形状像 F10 的历史深度限制，而不是当期在漏。

|---|---:|---:|---:|
| cash | 91,695 | 98.5% | 98.3% |
| interest_bearing_debt | 82,510 | 88.6% | 88.4% |

`goodwill` 一行读法：**在确实取到过的 93,104 行里，35.3% 有商誉、64.7% 源确认无商誉。**
分年度看覆盖率是逐年上升的（2018 年 NULL 57% → 2025 年 NULL 49%；2025 年报
5,205 行里 2,634 行有商誉 = 50.6%），这与商誉会计科目的实际历史趋势一致，
不是回填进度的产物。

## 四、验收口径的替换（母方已裁定，此处备案）

- 批10-b 的验收从"goodwill 有值率 ≥85%"改为**"取到率报告"**：交事实，不设百分比目标。
- 方案 3（把源的 null 写成 0）**否决**；方案 2（加 `goodwill_missing` 之类语义标记列）
  **挂起**，等到有真实消费方（质量门/估值要用商誉）时按需求排期。
- 若将来要消费 `goodwill`，必须先解决的是 **NULL 的语义**：现在 NULL 表示
  "源确认无此项目"与"该行没落地（0.22%）"两种情况混在一起，前者接近"0 商誉"、
  后者是未知。到那一步再定标记列，不用现在猜。

## 五、与 no_data 归因的关系

`docs/no-data-inventory.md` 处理的是"整只票没有任何数据"（334 只，其中 321 只是
北交所映射缺陷）；本文档处理的是"票在体系内、但某列没有值"。两份都用
`scripts/` 下的只读脚本现生成，不手写数字。
