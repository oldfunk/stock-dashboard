# 价值投资方法论完善方案（P0）

> 创建：2026-10-23 · 上游：`docs/roadmap.md` · 状态：**现行（长线迭代中，进度见 `docs/tasklist.md`）**
> 边界：母项目负责**价值投资的分析与展示**；组合层面（仓位 sizing / 集中度 / 再平衡）归纸盘子项目。

## 0. 为什么做（专业价值投资视角）

现有方法论（7 门规 + 五维评分 + AI 分析）在**纪律框架**上已相当完整，但存在两处结构性缺口：

1. **估值不可复现**：`intrinsic_value` 由 LLM 主观给三档（prompt 明确"方法自选、禁用固定倍数"），适合"思考"，但**不可复现 / 不可审计 / 不可回测**；`margin_of_safety` 也是 LLM 填的，不是"价格 vs 模型估值"算出来的。
2. **质量度量是"会计指标"而非"经济质量"**：缺 ROIC vs 资本成本、增量 ROIC/再投资率、资本密集度（维护性资本开支）、净负债/EV 视角；数据底座缺完整三表关键字段，导致估值模型算不出 owner earnings。

专业价值投资的四条线（好生意 / 好价格 / 好纪律 / 可验证）中，"好纪律"已是强项，缺的是**好价格的可复现性**与**可验证的闭环**。

## 1. 现状基线（2026-10-23 生产）

- 五维权重：护城河(ROE)0.30 / 估值(PE)0.20 / 增长 0.20 / 财务健康 0.15 / 定价权(毛利率)0.15。
- `financial_history` 字段：ROE/毛利率/净利率/OCF/利息覆盖/FCF/ROIC/EPS/总股本（**无折旧摊销、资本开支、营运资本、有息负债、货币资金、商誉、披露日期**）。
- 股息：`dividend_annual` 3620 只（年报现金分红），但 `stock_snapshot.dividend_yield` 仅 **783/5527**（回填缺口）。
- 收益验证：`analysis_outcome` 780 行（20 日 766 / 60 日 256 / 120 日 0）；只验"信号→收益"，**不验安全边际预测力**。
- `scripts/backtest_topk.py` 仍坏；无 look-ahead-safe 回测。

## 2. 缺口与迭代项（按依赖排序，逐项交付）

> 每项：目标 → 数据源 → 实现 → 单测 → **生产 Pi 验收**。"每次只做一件小而实的事"。

### P0-1 股息率 / 分红率回填（数据已有，立即）

- **缺口**：3619 只有股息数据、5206 只有现价，但仅 783 只有 `dividend_yield` → 红利池 fail-closed 常被误判为"阈值太严"。
- **数据源**：`dividend_annual`（最新年报 `cash_per_share`）× `stock_snapshot.current_price`。
- **实现**：`scripts/backfill_dividend_yield.py`；`yield = cash_per_share / price`，`payout = cash_per_share / EPS`；缺价/缺分红保持 NULL（不零填）。
- **单测**：计算口径 + 空值保持 + 幂等重算。
- **验收**：生产 Pi 跑后 `stock_snapshot.dividend_yield` 783 → **>3000**；红利池候选数 >0。

### P0-2 分红历史（可持续性）

- **缺口**：无法区分"连续稳定分红"与"一次性/特别分红"。
- **数据源**：`dividend_annual` 按年聚合（已有 `report_date` + `cash_per_share`）。
- **实现**：派生 `dividend_years`（近 10 年分红年数）、`dividend_per_share_series`；写入 snapshot / summary。
- **单测**：连续性计算（中断即重置）。
- **验收**：红利候选标注"连续 N 年分红"；一次性高分红被识别并降权。

### P0-3 资产负债表关键字段（估值分母 / 清算价值）

- **缺口**：缺货币资金、有息负债、商誉 → 无净负债、无 EV、无清算价值。
- **数据源**：akshare `stock_zcfz_em`（资产负债表，年报）或东财 datacenter 兜底。
- **实现**：落 `financial_history` 新列（`cash`/`interest_bearing_debt`/`goodwill`/`equity`）+ `financial_summary` 派生（`net_debt`、`ev`）。
- **单测**：净负债 = 有息负债 − 货币资金；EV = 市值 + 净负债；商誉/净资产占比。
- **验收**：详情页显示净负债、EV；估值模型可切换 EV/EBITDA 口径。

### P0-4 现金流关键字段（owner earnings 前提）

- **缺口**：缺折旧摊销、资本开支、营运资本变动 → owner earnings / 维护性资本开支座不清。
- **数据源**：akshare `stock_xjll_em`（现金流量表，年报）。
- **实现**：落 `financial_history` 新列（`depreciation`/`capex`/`working_capital_change`）。
- **单测**：`owner_earnings = 净利润 + 折旧摊销 − 资本开支 − 营运资本增加`；与 FCF 口径交叉校验。
- **验收**：估值模型有 owner earnings 输入；维护性资本开支占比可见。

### P0-5 历史价格序列 + 历史估值分位（相对估值）

- **缺口**：只有绝对门槛（PE 3–20 一刀切），缺自身历史分位与同业分位。
- **数据源**：akshare `stock_zh_a_hist`（前复权历史行情）；财务历史已有 10 年。
- **实现**：补 `kline_daily` 覆盖（候选池 + 回测标的）+ 落历史 PE/PB/股息率序列；派生 5/10 年分位。
- **单测**：分位计算（滚动窗口、缺失处理）。
- **验收**：详情页显示"PE 处近 5 年 X% 分位"。

### P0-6 可复现估值模型（核心）

- **缺口**：估值靠 LLM 主观，不可复现/审计/回测；安全边际是填的。
- **数据源**：P0-3/P0-4 的三表关键字段 + 现有 ROIC/FCF/EPS。
- **实现**：`src/analyzer/valuation.py`：
  - **Owner Earnings 折现**（稳定现金牛）：`OE = 净利润 + 折旧摊销 − 维护性资本开支 − 营运资本增加`，三档折现率；
  - **FCF 折现**（成长/周期）；
  - **重置成本 / 清算**（周期/困境，明说局限）；
  - 输出 `intrinsic_value{conservative/base/optimistic}` + `margin_of_safety = 1 − price / base`。
  - 假设显式（增长率/折现率/利润率），同一假设 → 同一结果。
- **AI 分工调整**：LLM 从"给估值"改为"校验模型估值 + 解释偏离 + 补模型未覆盖的定性项"（moat/management）。
- **单测**：固定输入 → 固定输出；边界（FCF 为负、字段缺失）→ 明确"数据不足"，不硬算。
- **验收**：详情页显示模型估值与安全边际；估值可复现（重跑结果一致）。

### P0-7 同业 / 行业估值分位

- **数据源**：行业（申万/东财）聚合 + P0-5 历史分位。
- **实现**：扩展现有 `sector_avg` 为"行业 PE/PB/ROE 中位数 + 个股分位"。
- **验收**：详情页显示同业分位，避免"跨行业绝对 PE"误判。

### P0-8 look-ahead-safe 回测

- **缺口**：`backtest_topk.py` 坏；`financial_history` 无披露日期（前视风险）。
- **数据源**：披露日期（P0-10）+ 历史财务 + P0-5 历史价格。
- **实现**：T 日收盘后只用 **T 日及之前已披露** 的财务；T+1 成交；费用/滑点口径与纸盘一致（子项目 `engine/rules.py` 同口径）。
- **单测**：构造"未来数据"验证不被使用（前视隔离）。
- **验收**：脚本可跑；回测与实盘口径对照通过。

### P0-9 买入安全边际（MOS）记录与预测力验证

- **缺口**：outcomes 只验信号收益，不验"折让大的更安全/更好"。
- **数据源**：P0-6 的 MOS + `analysis_outcome`。
- **实现**：每次分析落 `margin_of_safety_at_entry`；outcomes 按 MOS 分层统计收益/回撤。
- **验收**：产出"安全边际分层收益表"，验证 MOS 是否有预测力。

### P0-10 `financial_history` 披露日期

- **缺口**：无 `notice_date` → 回测前视风险。
- **数据源**：东财 datacenter `REPORT_DATE`/`NOTICE_DATE`，或显式标注"仅回测不用"。
- **实现**：加列 + 采集回填；回测强制使用披露日期。
- **验收**：回测可用披露日期过滤未来数据。
