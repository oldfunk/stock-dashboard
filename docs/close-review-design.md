# 收盘检阅与投资笔记融合（设计草案，2026-11-24）

> 上游：用户方向——"AI 整理市场信息融合进投资笔记，每天收盘检阅今日要闻"。
> 定位：**价值投资的信息消化层**，不是新闻流、不是情绪交易信号。
> 状态：设计草案；先做 3 天离线原型与评估集，再决定是否进生产线。

## 1. 现状盘点（先看清已有东西）

| 已有 | 位置 | 现状/问题 |
|---|---|---|
| 新闻采集 | `src/collector/news_fetcher.py`（S? 财联社/同花顺） | 7–23 点每 15 分钟轮询；`news_item` 599 条（11-23 最新）；有 code/name/title/summary/url/source/published_at/sentiment/ai_brief |
| 舆情日报 | `src/analyzer/news_summarizer.py` → `news_digest` | 每天 18:30 两次 LLM：逐条情绪 + Markdown；**偏短线/资金面**（"牛散方文艳""短期调整压力"），无引用、无论点/红线关联 |
| 投资笔记 | `ai_journal` + `/journal` | **周度**复盘（WatchlistReviewer）+ 大盘解盘；不是每日；与舆情日报是两张皮 |
| 面板 | `/journal` | 展示最新笔记 + 当日 digest；没有"收盘检阅"工作流、无来源链接、无确认状态 |
| 持仓/观察池 | `paper_account.db`、`watchlist`、`watchlist_thesis` | 可用作相关性排序与红线检测，但新闻侧没有实体链接 |

**结论**：数据与调度已具备，缺的是**价值视角的编排、实体关联、笔记化与检阅工作流**。

## 2. 产品定位（必须写死的几条）

1. **新闻是论点/风险的输入，不是买卖触发器**。笔记里明确"新闻不构成买卖指令"；
   纸盘仍只走母策略 signal/buy_zone/stop。
2. **四问输出**：今天市场发生了什么（事实）→ 对我的持仓/观察池/候选意味着什么（影响）
   → 哪些论点/红线被触及（维护）→ 明天要看什么（关注）。
3. **事实与解释分层**：事实带 `news_item.id/url/时间`；AI 解读单独成段，不许混写。
4. **没有要闻是合法输出**：宁可"今日无影响级要闻"，不许凑字数。
5. **一条笔记/天**：落在 `ai_journal` 的当天条目，草稿→人工确认；周度复盘继续聚合。

## 3. 功能拆解（F 线）

### F1 收盘检阅流水线（15:45，收盘后）

```
新闻入库（已有）→ 去重/聚类 → 实体链接（code/行业/主题）→ 相关性排序
（持仓 > 观察池 > 候选 > 宏观）→ 论点/红线匹配（watchlist_thesis）
→ LLM 结构化事实表 + Markdown 笔记 → 落 news_digest + ai_journal 草稿
→ 面板"今日收盘检阅"
```

- 时间：15:45 首跑（新闻与公告已定稿），失败/源晚到 18:30 重试；幂等按日期。
- 成本：每天 1 次（结构化 + 正文两次调用，沿用现有"JSON 与 Markdown 分开"的做法）；
  上限 30 条，超出按相关性截断。
- 失败：某源不可用 → 笔记里标 `unavailable` + 原因；无新闻 → "今日无可用要闻"。

### F2 笔记融合（`ai_journal` 扩展）

每日笔记模板（可编辑）：

```
# YYYY-MM-DD 收盘检阅
## 1. 市场事实（指数/成交/涨跌家数，带 asof）
## 2. 持仓与观察池（每条：新闻事实 → 影响 → 是否触及论点/红线）
## 3. 候选池（只列与候选相关的信息，不覆盖全部 20 只）
## 4. 纪律（今日计划执行/拒单/NAV；新闻不得触发交易）
## 5. 明日关注（≤3 条，可验证）
## 6. 来源（news_item id + url + 时间）
```

- 状态：`draft`（AI 生成）→ `confirmed`（用户确认）/`edited`；
- 周度复盘读取本周已确认笔记，做聚合，不重复生成；
- 同一天多次运行只更新草稿，不覆盖用户编辑（version/updated_at）。

### F3 检阅工作流（把"打磨"变成日常）

- 面板清单：要闻已读 / 持仓公告 / 计划执行 / NAV 完整 / 明日关注；
- "确认检阅"一次记录（不进交易，只进笔记元数据）；
- 连续未确认/无笔记 → 面板提示（不自动开交易）。

### F4 面板

- 首页"今日要闻"卡：只放与持仓/观察池/候选相关的 Top 3，带来源；
- `/journal` 日视图：事实/影响分层、来源可点、与昨日 diff（新增/消失的要闻）；
- 过滤：持仓 / 观察池 / 候选 / 宏观；"无要闻"空态。

### F5 评估（先于"打磨"）

- 标注集：20–30 条真实新闻 × 相关性（持仓/观察池/候选/无关）+ 是否触及红线；
- 指标：引用率（每条事实都有来源）、相关性 precision/recall、用户编辑时长、
  "无要闻"是否正确、是否出现买卖建议（应为 0）；
- 离线脚本先跑 3 天真实数据，再谈上线。

## 4. 数据与架构建议

- **不新建第二套笔记系统**：扩展 `ai_journal`（`note_type`、`status`、`sources_json`、
  `review_state`）；`news_digest` 增加 `kind`（`sentiment|close_review`）。
- 新闻侧：`news_item` 增 `entities_json`（codes/sectors/themes）、`cluster_id`（去重）；
  能复用则不新建表。
- 新模块：`src/news_review/`（normalize/link/rank/prompt/persist），web 只读渲染；
  不允许在 web 路由里调 AKShare/LLM。
- 调度：`news.review_time`（默认 15:45）+ 18:30 重试；与现有 `_check_news_jobs` 同线程模式。
- 契约：每条事实必须能追溯到 `news_item.id`；来源失败显式标注；不用旧闻冒充今日。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 变成短线情绪/资金流日报（现状问题） | 提示词以"论点/风险"为目标；禁止"短期涨跌/资金流向"式结论；评估集拦截 |
| 新闻噪音/重复 | 聚类去重、相关性阈值、每日上限、无要闻空态 |
| 幻觉/无来源 | 事实必须引用 id/url；AI 解读单独段落；来源缺失标 unavailable |
| 诱发频繁交易 | 明确"不构成买卖指令"；纸盘策略不受新闻影响；只更新论点/红线 |
| 成本/延迟 | 1 次/日 + 上限 30 条；失败重试 18:30；缓存 |
| 用户不信任/不读 | 一页、Top 3、可编辑、diff、确认清单；先 3 天原型验证 |

## 7. 需要用户拍板的三件事

1. **笔记归属**：AI 只出草稿、必须人工确认（推荐），还是自动发布？
2. **范围**：只做"收盘检阅"，还是也做盘中事件提醒？（推荐先只做收盘）
3. **是否纳入纸盘 P&L/决策**：笔记里带"今日计划/成交/NAV"（推荐 F1 就带），
   还是纯信息层？
