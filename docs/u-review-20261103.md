## U1 撤回：DuckDB 能读到未 checkpoint 的 WAL 数据

原疑点：`export_snapshot` 用 `ATTACH ... (TYPE SQLITE, READ_ONLY)` 直连业务库，却没先
`PRAGMA wal_checkpoint(TRUNCATE)`，于是"还在 -wal 里的最新数据可能进不了快照"。

证伪方法（最小实验，不碰生产库）：建一个 WAL 库 → 写 10 行 → 再写 20 行并提交但**不**
checkpoint（确认 `-wal` 仍有 16,512 字节）→ 用全新的 DuckDB 连接 ATTACH 计数 → 再 checkpoint 复测。

```
本机  duckdb 2.0.0 / sqlite 3.50.4   python G:/qoder/u1_wal_experiment.py
  阶段0 sqlite 计数 10 | DuckDB ATTACH 看到 10 行
  阶段1 sqlite 计数 30（新 20 行只在 -wal 里，16512 字节）| DuckDB ATTACH 看到 30 行，末批标签=wal
  阶段2 checkpoint 后（-wal 归零）| DuckDB ATTACH 仍 30 行
nec   duckdb 1.4.2 / sqlite 3.45.1   /tmp/u1_wal_nec.py（同一脚本改路径）
  完全一致：阶段1 就看到 30 行
```

结论：**WAL 内已提交数据对 DuckDB 可见**，不存在"少一段最新数据"的洞，因此不加
`wal_checkpoint`（加了反而会在回填/流水线持锁时抢锁、制造 `database is locked`）。
诚实标注本实验的边界：它证的是"已提交数据可见"；**未提交事务**的数据本来就不该进快照，
不是本条目讨论的范围。

## U3 撤回"长事务"：确实是一个事务，但只有 0.1–0.2 秒

原疑点：`backfill_dividend_years` / `backfill_snapshot_dividends` 把全市场逐行 UPDATE 放进同一
事务，可能长时间持写锁。

实测（生产规模：5,568 只快照 / 22,272 条分红，写进 `/tmp` 的临时库，第二连接用
`BEGIN IMMEDIATE` 轮询探测阻塞）：

```
nec（.venv/bin/python /tmp/u3_lock_nec.py，sqlite 3.45.1）
  backfill_snapshot_dividends  墙钟 0.122s | 第二连接被挡 31 次（timeout=0，立即失败）
  backfill_dividend_years      墙钟 0.196s | 第二连接被挡 25 次
本机（同一脚本，sqlite 3.50.4）
  0.040s / 0.054s，最长一次等待 1.4ms
```

结论：**"单事务"是事实，"长事务"不是**——产线规模下 0.1–0.2 秒级，且这两段全程无网络调用
（分红拉取 `refresh_dividends` 是先取数后一次 `upsert_many`，不持锁跨网络）。
收益不抵风险（分批提交会把幂等性打散：中途失败会留下"一半清零一半未回填"的中间态），
所以不改。真正需要长事务纪律的地方（回填脚本）已经由 `--max-seconds` + 逐只记账处理。

## U7 成立并已修：股息分位改 PIT，不再等于价格分位的倒数

旧实现：`_dividend(code)` 只取库里最新一条分红，然后把这**一个常数**除以往返每一个
交易日的价格。于是 `dy = 常数 / price`，它的"分位"就是股价分位的倒影——分红增派或
减派在历史序列里完全不存在。

修法（`f079ad9`）：`_dividends(code)` 取出全部 (report_date, cash_per_share) 并
LEFT JOIN `financial_history` 拿同报告期的 `notice_date` 作为披露时点；
`_cash_at(dividends, day)` 取"当日已披露的最近一期"，缺披露日的分红行不参与
——与 `_report_at` 对年报的规则一字一致。4 条用例：

```
单元：FY2020(notice 2021-04-30, cash 2.0) + FY2022(notice 2023-04-30, cash 0.4)
  2021-01-15 -> None（都未披露）；2021-05-15 -> 2.0；2023-03-15 -> 2.0；2023-05-15 -> 0.4
端到端：价格 100→80、EPS 恒定
  PIT 下 dy 序列 2.0(20 点) / 2.5(4 点) / 0.5(8 点)，当前 0.5 → dy_pct = 25.0
  旧口径把 0.4 套满全历史 → dy_pct = 100.0（"股息率历史最高"全是股价下跌的倒影）
边界：窗口内无任何已披露分红 → dy_pct 为 None，PE/PB 照常出（不因一侧缺数整体失效）
```

既有 `test_valuation_percentile_20261023.py` 5 条保持全绿（那条只有一条分红，PIT 与旧口径
本就等价），说明这次只修掉了错的那部分。变异 X1（退回"取最新一条套全历史"）→ 4 红、
X2（忽略披露时点）→ 3 红、X3（缺披露日回退报告期）→ 1 红。
